## 1. Runtime flow — the two NLU paths (the "dual parser")

`lb "<request>"` → `cli.main` (`src/linuxbuddy/cli.py`):

- **`--reset` / `--frame`** are session control flags (clear / dump the session
  frame as JSON).
- Multi-turn is **opt-in** via `$LINUXBUDDY_SESSION` (the zsh widget exports it;
  the owner's bash also exports it — see memory). Set → `_run_session`; unset →
  `_run_single_turn`. A bare `lb "..."` (and the 147-row sweep) takes single-turn.

### Path A — single-turn (`_run_single_turn`)
`nlu.parse(request)` → `Frame | None`.
- **`nlu.parse`** (`nlu.py:430`) runs an ordered **router** of domain parsers
  (`_ROUTER`). Each returns a `Frame` (matched), `None` (not mine, try next), or
  the `_ABSTAIN` sentinel (mine but compound/underspecified — stop, don't let a
  later domain guess a fragment). `file_discovery` is **last** so a bare extension
  still routes to `find_by_type`.
- If `frame is not None` → `_emit_frame(frame, None)`.
- If `frame is None` (rules abstain) → **the single encoder seam**:
  `hybrid.classify_fallback(request)` → `(Frame, info) | (None, {})`. A frame →
  `_emit_frame(frame, info)`; else `abstain_hint(request)` or the generic abstain
  message to stderr, exit 1.

### Path B — multi-turn (`_run_session` → `_session_dispatch`)
`session.classify(request, frame)` → `(act, delta)`, `act ∈ {reset, new, refine,
operate, fallback}` (rules only — `session.py:278`):
- **reset** → clear; if a remainder, re-dispatch it fresh.
- **new** → `SessionFrame.from_request` (a composable find) or, if nothing
  composable, `_run_single_turn`.
- **refine / operate** → merge the delta into the existing `SessionFrame`
  (or `_run_single_turn` if no frame).
- **fallback** → `_run_single_turn`.
Then `SessionFrame.to_command_plan()` → a plain `Frame` (`session_find` /
`session_count` / `session_find_biggest`) → the SAME emit pipeline. A
compile/render failure → `_run_single_turn` (safe default).

**Consequence:** the encoder is consulted **only on a single-turn abstain** —
including when the session layer falls back to single-turn. It never sees a turn
the session layer handled, nor a request the rules routed to a (possibly wrong)
command.

## 2. The shared emit pipeline (`_emit_frame`, identical for rules & encoder)

`compile(frame)` (`planner.py`) → typed argv plan (reads KB `base_argv` with
`{slot}` placeholders; an unresolved placeholder → `PlanError` → abstain) →
**`gate.check(risk_ops(frame.intent), os.getcwd())`** → `to_shell(argv_plan)`
(`render.py`) → print command to **stdout**; exit **0** (read) or **3**
(destructive). Abstain/denial → stderr, exit **1**, nothing on stdout.

- **Encoder confidence marker** (`cli.py:102`): when `info["source"]=="encoder"`,
  a line is printed to **stderr** ("LinuxBuddy ~ interpreted (language model) —
  review before running", or a DESTRUCTIVE variant). stdout stays exactly the
  command (the widget buffer contract). *This marker is how the dogfood detects
  encoder- vs rules-sourced commands.*

## 3. The gate (`gate.py`)

Destructive = `risk_ops ∩ {write, delete, privilege}` (`DESTRUCTIVE_OPS`). In
prototype mode (default), a destructive plan is emitted only when `cwd` is under
`config.maze_root()` (resolved with `realpath` + `commonpath`, so `..`/symlinks
can't slip the cwd check). Read-only works anywhere. Prod mode lifts the gate.
**The gate is cwd-based by design** — it does not inspect the target path, so a
`../..` target inside the maze is emitted (settled limitation; `lb` never
executes).

## 4. KB intents vs `label_space.json`

- KB = per-domain YAML (`kb/commands/*.yaml`); `load_kb()` yields `intent → spec`
  with `base_argv`/`and_argv`/`pipe*_argv` (`{slot}` placeholders) + `risk_ops`.
- `data/label_space.json` (frozen) lists the **85** plain KB intent ids (= the
  exact `frame.intent` the planner uses), each intent's domain, the 5 dialogue
  acts, and `_ABSTAIN`. Generated by `ml.labels` from `load_kb()` — not hand-edited.
- **Encoder label space = these 85 intents**, but it can only *predict* intents it
  has training data for: **27 of 85 are zero-data** (listed in DATA_CARD.md), so
  the encoder never resolves those — the rules remain their only handler.
- Risk/shape per intent (from the KB, used to label the dogfood): e.g.
  `delete_file`→`rm`(delete), `move_file`→`mv`(write), `copy_file`→`cp`(write),
  `make_dir`→`mkdir`(write), `make_executable`/`set_permission`→`chmod`(write),
  `kill_process`→`pkill`(write), `check_syntax`/`run_script`→`python3`(**write** —
  gated), the `find_by_*`/`count_files`/`find_largest` family→`find`(read).

## 5. Slot filling & where constraints combine (the crux for the proposal)

- **Single-turn `_parse_file_discovery`** (`nlu.py:339`) detects ext, size, time
  (minutes/days), name, path **independently**, then applies a **precedence:
  size → time → name → type → abstain** (`nlu.py:394`). Crucially, the `ext` slot
  is added to `slots` BEFORE the precedence return, so it **rides along** with
  whichever intent wins. Measured consequence (dogfood, not inference):
  - type+size composes → `find . -type f -name '*.csv' -size +1M` ✅
  - type+time composes → `find . -type f -name '*.csv' -mtime -7` ✅
  - **but size+time does NOT**: `size` returns first, so `days` is never added →
    the time constraint is **silently dropped** (e.g. "json over 1mb from the last
    2 days" → `find_by_size` with the `-mtime` lost).
  - **multi-extension drops**: `_detect_ext` returns ONE extension, so "csv and
    json" keeps only one.
  Invariant #6 is honored per-intent (no defining slot → abstain, not a
  match-everything find). So the single-turn path composes *type + one of
  {size,time}* but drops the **second** of {size,time} and the **second
  extension** — a narrower silent-drop than "keeps only one constraint".
- **Multi-turn `SessionFrame`** (`session.py`) DOES compose: `targets` (path,
  name) + `filters` (size, mtime) are accumulated by `merge()` across refine
  turns, so type+size+time co-exist — but only when built up turn-by-turn, not
  from a single compound utterance.
- **Definite reference** (`nlu.py:472`, `_DEFINITE_GLOBS`): "the logs"→`*.log`
  etc. resolve to a glob (emitted unquoted via `render.Raw`). Generic references
  with no implied type ("the config file", "this file") have no glob → keep
  abstaining (the documented residual).
- The encoder path reuses these detectors (`hybrid.fill_slots`) plus encoder-only
  heuristics (spreadsheet→csv, "last day"→days), and abstains if a find_*'s
  defining slot can't be extracted (Task 39 invariant-#6 guard).

## 6. Thresholds & artifact paths

- `ml_config.yaml`: `encoder.enabled`, `model_path=models/ft-minilm-l6`,
  `t_read=0.55`, `t_destructive=0.68`, `margin_min=0.05`. Kill switch
  `LINUXBUDDY_ENCODER=0`.
- Runtime encoder = **ONNX fp32**, torch-free (`ml/onnx_encoder.py`):
  `models/ft-minilm-l6/onnx/encoder.onnx` + `index_onnx.npz` (85 cached
  description embeddings) + `tokenizer.json`. Imports only onnxruntime +
  tokenizers + numpy, lazily on abstain. Live `lb` runs from `.venv`
  (Python 3.14) which now has numpy + onnxruntime + tokenizers (no torch).
- Degradation: missing `.onnx`/deps or kill switch → pure v1.
